# histeclipse

An interactive 3D explorer for solar and lunar eclipses across recorded history and into the future, built as a fully static site.

The site is static and hosted on GitHub Pages. Every computation either runs in the browser or is precomputed into static data files, so there is no server.

## Development

Requires Node.js ≥ 22.12 (see `.nvmrc`) and pnpm 10.

```sh
pnpm install
pnpm dev          # local dev server
pnpm check        # everything CI runs: format, lint, typecheck, tests + coverage, build
```

### How `src` is layered

Folders sit in tiers, and imports only go down (lint enforces it; see `eslint.boundaries.js`):

1. `core`, `util`: shared vocabulary and helpers.
2. `astro`, `time`, `eclipses`, `deepTime`, `data`: the domain.
3. `state`, `sources`: what the reader is looking at, and where each thing shown comes from.
4. `globe`, `sky`, `story`, `tablets`: drawing it.
5. `ui`, `telemetry`, `text`: the page around it, and the texts to search.
6. `features`: one folder per feature, on one contract (`features/feature.ts`).
7. `app.ts`, `main.ts`: the wiring.

The few imports that still go up are listed there as exceptions, to be removed, not added to. `src/architecture.test.ts` checks two more things that may only shrink: the imports between folders that close a cycle, and the methods on the globe's interface (draw new things with `globe.addLayer`). No file in `src` may pass 400 lines (`MAX_LINES` in `eslint.boundaries.js`; tests aside): lint fails, so new work goes into a feature (`src/features/`), a globe layer or a new file. The files already longer are listed in `LINE_LIMITS` at their sizes and may only shrink; the architecture test asks for a limit to come down when its file shrinks by more than 50 lines, and for the entry to go once the file is within 400. The same goes for the counts (`startApp`'s top-level `let`s and conditionals, the globe's methods): each may sit a little under its limit. Lower a limit only when the test asks, not in every PR that shortens a file, so PRs written side by side don't all edit the same line (#479). Functions have limits too: 80 lines of code and a complexity of 15 (`MAX_FUNCTION_LINES`, `MAX_COMPLEXITY`). The files with functions over them when the rule came in are listed in `FUNCTION_LIMITS`, with how many each has, and that count may only come down (#489). Each feature in `src/features/` keeps its own pieces: a module in `ui`, `globe`, `story`, `sky` or `tablets` that one feature alone uses moves into that feature's folder, and from outside a feature only its `index.ts` is imported (#487). The wider plan is in #384.

Styles live beside the code they style: a component imports its own `.css` file (as `globe/layerHost.ts` imports `nameLabels.css`), and `src/style.css` keeps the page-wide rules and the styles not yet moved (#382).

## Deployment

Each merge to `main` builds the site with its commit SHA stamped into a `<meta name="histeclipse-version">` tag and deploys it to GitHub Pages, served at **https://histeclipse.limits.world/** through Cloudflare (which sets the caching and security headers; the old `serroba.github.io/histeclipse/` address redirects there). The Playwright scenarios tagged `@live` then run against that address, but only after the public URL is serving that exact commit. The whole suite runs against it daily and can be started by hand (_Actions → Live smoke test_).

## Data pipeline

`data-pipeline/` is a Python project that generates the static data files offline. It never runs on the site. It requires [uv](https://docs.astral.sh/uv/).

```sh
cd data-pipeline
uv sync
uv run ruff format . && uv run ruff check .   # format + lint (all ruff rules)
uv run mypy && uv run basedpyright            # two strict type checkers (see typings/README.md)
uv run pytest                                 # tests + property tests, 95% coverage gate

# Generate data (downloads ~600 MB of DE441 excerpts once, into data-pipeline/.cache/)
uv run histeclipse-pipeline fetch-ephemeris
uv run histeclipse-pipeline lunar-catalog --out ../public/data/lunar
uv run histeclipse-pipeline solar-catalog --out ../public/data/solar   # with Besselian elements
uv run histeclipse-pipeline delta-t --out ../public/data/delta-t.json
uv run histeclipse-pipeline calendars --out ../public/data/calendars   # Babylonian and Chinese months
```

Positions come from [JPL DE441](https://ssd.jpl.nasa.gov/planets/eph_export.html), via [Skyfield](https://rhodesmill.org/skyfield/). Results are checked against NASA's _Five Millennium Canon_ (Espenak & Meeus). Skyfield's ΔT model is the Morrison–Stephenson–Hohenkerk–Zawilski spline, and every catalog records which model it used. The ΔT table reaches back to 9700 BCE, the Holocene's start, by the long-term parabola of Stephenson, Morrison & Hohenkerk (2016), with an uncertainty that grows to about ±3 hours there; the eclipse catalogs are computed from 4000 BCE, and before then the Moon's and planets' positions in the sky view are not checked against DE441.

## Contributing

- `main` is protected. Every change goes through a small, focused pull request.
- PRs merge by squash only, after the `CI OK` check passes and the branch is up to date with `main`.
- Dependencies are pinned to exact versions. pnpm refuses package versions younger than 7 days (`minimumReleaseAge`), and uv excludes releases newer than 7 days (`exclude-newer`), and Dependabot uses the same cooldown.
- GitHub Actions are pinned to commit SHAs and audited with [zizmor](https://github.com/zizmorcore/zizmor).

The pipeline's `polarity` command fetches PmagPy's source at a pinned commit, checks its checksum, and reads the table from the code's syntax tree without running it. Before 83 Ma the site shows the superchrons, and a field reversing too often to draw between them; before 540 Ma, nothing.
- Radiocarbon: the calibration curves [IntCal20](https://doi.org/10.1017/RDC.2020.41) (Reimer et al. 2020) and [SHCal20](https://doi.org/10.1017/RDC.2020.59) (Hogg et al. 2020), CC BY 4.0, as the IntCal group publishes them; the pipeline's `radiocarbon` command fetches them pinned by checksum. Miyake events from Miyake et al. 2012 and 2013, O'Hare et al. 2019 and Brehm et al. 2022; L'Anse aux Meadows from Kuitems et al. 2022.
- Earth imagery: [NASA Blue Marble Next Generation](https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/) (April 2004, topography and bathymetry), downscaled to 2048 × 1024; close up, a sharper 8192 × 4096 (4096 × 2048 on phones) is fetched from the 21600 × 10800 release by the pipeline's `planet-maps` command, pinned by checksum. It shows today's coastlines and ice. The night side is deliberately a plain dark tint, because modern city lights would be anachronistic.
- Moon and planet imagery, close up: the Moon is the [NASA CGI Moon Kit](https://svs.gsfc.nasa.gov/4720) (LRO camera mosaic). Mercury is MESSENGER's mosaic [PIA15063](https://science.nasa.gov/photojournal/a-global-view-from-orbit/) (NASA/JHU APL/Carnegie Institution of Washington, 2011), brightened. Mars is the [Viking colour mosaic](https://astrogeology.usgs.gov/search/map/mars_viking_global_color_mosaic_925m) (NASA/JPL/USGS, images of 1976–80). Jupiter is Cassini's map [PIA07782](https://science.nasa.gov/photojournal/cassinis-best-maps-of-jupiter-cylindrical-map/) (NASA/JPL/Space Science Institute, December 2000). Each is fetched by the pipeline's `planet-maps` command, pinned by checksum and shrunk to 2048 × 1024; close up, a sharper one is fetched (Mercury and Mars 4096 wide, Jupiter its own 3600, the Moon the kit's 4096). All are public domain. Venus shows its cloud tops as a plain colour, because from space the clouds hide the ground. Saturn keeps painted bands, because no global map of it from a mission is used. Each planet is turned as it was at the moment shown by the IAU rotation models ([Archinal et al. 2018](https://doi.org/10.1007/s10569-017-9805-5)), allowing for the light's travel time, and checked against JPL Horizons; Jupiter's and Saturn's turning is their interiors' (System III), which their clouds drift against.
- Sun imagery: NASA's [Solar Dynamics Observatory](https://sdo.gsfc.nasa.gov/) (courtesy of NASA/SDO and the AIA and HMI science teams), rendered through [Helioviewer](https://helioviewer.org/) (NASA/ESA). Six channels, at solar maximum: visible light and the magnetic field from HMI, and 304, 171, 193 and 131 Å from AIA. For each, four images taken about a week apart, from 18 April to 8 May 2024 (12:00 UT), are stitched into a map of the whole surface, so it shows each part as it was when it last faced Earth, not one moment; the poles, which SDO barely sees, are smoothed in from nearby latitudes. The side facing Earth is the image of 8 May 2024. This is the modern Sun: its surface on any other date, and certainly in antiquity, was different and is unknown.
- Borders of past states and empires: [Cliopatria](https://github.com/Seshat-Global-History-Databank/cliopatria) v0.2.1, Seshat Global History Databank (Bennett et al. 2025, _Scientific Data_ 12, 247), licensed [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). For this site the borders were simplified to about 10 km, holes and areas smaller than about 30 km across were dropped (a state with nothing larger keeps its largest area, simplified to about 1 km), consecutive periods with unchanged borders were merged, BCE years were converted to astronomical numbering, and the data was split into one file per century. As Cliopatria's authors note, the borders are one reading of the evidence; past borders are often uncertain or disputed.

Magnitudes follow the Astronomical Almanac formulas given by Meeus (_Astronomical Algorithms_, ch. 41), with Saturn's rings.
